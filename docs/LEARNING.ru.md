# Разбор PCInspector

Новая вкладка **Processes** разобрана в разделе 9 в конце этого файла.

Это первая рабочая версия для портфолио. Цель — уметь запустить её, объяснить
каждый этап сбора данных и самостоятельно добавить небольшой функционал.

## 1. С чего начинается программа

Открой `src/PCInspector/Program.cs`. Метод `Main` — точка входа.
`ApplicationConfiguration.Initialize()` настраивает WinForms, а
`Application.Run(new MainForm())` создаёт окно и запускает обработку его событий.
Атрибут `[STAThread]` нужен для корректной работы компонентов Windows UI.

## 2. Как устроено окно

`MainForm.cs` отвечает за поведение, `MainForm.Designer.cs` — за расположение
элементов. Ключевое слово `partial` позволяет записать один класс в двух файлах.
В этой версии расположение задано кодом; менять его следует в файле разметки.
`DataGridView` показывает строки таблицы, `Button` вызывает обновление.
`TableLayoutPanel` распределяет свободное место при изменении размеров окна.

## 3. Что происходит при Refresh

Проследи цепочку:

```text
Click → RefreshButton_Click → RefreshInfoAsync
      → SystemInfoService.GetSnapshot → SystemSnapshot → строки таблиц
```

Показ окна (`Shown`) вызывает тот же метод. Поэтому данные появляются сразу.
На время чтения кнопка отключается: второй сбор не должен начаться раньше первого.
В `finally` кнопка включается даже после ошибки.

`await Task.Run(...)` отправляет чтение в фоновый поток. Пока он работает,
главный поток продолжает обрабатывать окно. После `await` выполнение возвращается
в UI-поток, и можно обновить таблицы. `async void` здесь используется только для
обработчиков событий; обычный асинхронный метод возвращает `Task`.

## 4. Зачем отдельная модель

`SystemSnapshot` хранит результат одного чтения. Это обычные свойства и списки,
без кнопок и таблиц. Поэтому позже тот же результат можно будет экспортировать
в JSON, не запрашивая систему повторно.

`ulong?` означает «неотрицательное целое число либо отсутствие значения».
Ноль свободной памяти и неизвестный объём памяти — разные состояния.
`DiskInfo` — небольшой `record`, описывающий один том.

## 5. Откуда берутся сведения

Начни с `ReadCpu`: запрос `SELECT Name FROM Win32_Processor` похож на SQL,
но обращается к WMI — службе управления и диагностики Windows, а не к MySQL.
Цикл читает названия процессоров. `using` освобождает объекты WMI после работы.

`ReadOperatingSystem` получает название Windows, версию, сборку, память и время
загрузки. Память приходит в KiB, поэтому умножается на 1024. Для вывода в GiB
`DisplayFormat` делит байты на 1024³. Показывается RAM, доступная Windows,
а не сумма ёмкостей установленных планок.

`DriveInfo.GetDrives()` перечисляет логические тома. Перед чтением ёмкости
проверяется `IsReady`: у пустого картридера нельзя прочитать свободное место.

`NetworkInterface.GetAllNetworkInterfaces()` перечисляет сетевые адаптеры.
Оставляем активные, исключаем loopback и выбираем IPv4. Адресов может быть
несколько, поэтому рядом с каждым показывается название адаптера.

Uptime — разница между текущим временем и временем загрузки Windows.
Это не длительность работы PCInspector. Fast Startup может сохранять сеанс ядра;
после обычного выключения uptime не всегда сбрасывается.

## 6. Почему ошибка не закрывает приложение

`ReadSection` ловит ожидаемые ошибки чтения, например отказ WMI в доступе,
и записывает предупреждение. Остальные разделы продолжают работать.
Для каждого диска и адаптера есть дополнительная защита, чтобы один недоступный
элемент не скрывал остальные. Неизвестное значение выводится как `Unavailable`.

## 7. Как проверить и сделать своё изменение

1. Запусти проект по README и найди в коде строку, которая добавляет CPU в таблицу.
2. Поставь breakpoint в `RefreshButton_Click`, нажми Refresh и пройди метод отладчиком.
3. Первое небольшое задание: добавь строку «PCInspector version» со значением `0.1`.
4. Следующее задание: добавь число логических процессоров из `Environment.ProcessorCount`.
   Сначала добавь свойство модели, затем заполни его в сервисе и покажи в окне.
5. Собери проект и проверь новое значение. Удали временное изменение, если оно не нужно.
6. Сохрани осмысленное изменение отдельным коммитом:

```powershell
git status
git diff
git add src/PCInspector
git commit -m "feat: show logical processor count"
git push
```

Не выполняй пример коммита до того, как действительно добавишь этот функционал.
`git diff` показывает изменения, `git add` выбирает их для коммита,
`git commit` сохраняет локальную версию, `git push` отправляет её на GitHub.

## 8. Первая публикация

Создай на GitHub пустой **public** репозиторий `nully0df/PCInspector`, без README,
лицензии и `.gitignore`: они уже находятся в проекте. Если локальный коммит
подготовлен, а удалённый репозиторий всё ещё пуст:

```powershell
git remote -v
git push -u origin main
```

Команды выполняются из папки PCInspector. Если `origin` ещё отсутствует:

```powershell
git remote add origin https://github.com/nully0df/PCInspector.git
git push -u origin main
```

Если репозиторий на GitHub уже содержит коммиты, сначала согласуй истории;
не используй принудительную отправку `--force`.

## 9. Живая нагрузка процессов

Вкладка `System` по-прежнему читает характеристики по Refresh. Вкладка `Processes`
обновляется примерно каждую секунду, пока открыта программа.

Проследи цепочку из трёх файлов:

1. `ProcessSampler.cs`: получает процессы через `Process.GetProcesses()`, читает
   накопленное `TotalProcessorTime`, память `WorkingSet64`, PID, время запуска и путь.
2. `ProcessHistory.cs`: сравнивает два замера, вычисляет CPU и хранит последнюю минуту.
3. `ProcessesView.cs`: запускает чтение в фоне, выводит таблицу и историю выбранной строки.

CPU рассчитывается так:

```text
CPU% = (новое CPU-время − старое CPU-время)
       / прошедшее время / количество логических процессоров × 100
```

Пример: было 10 секунд CPU-времени, через секунду стало 12. На машине с 8 логическими
процессорами это `(12 − 10) / 1 / 8 × 100 = 25%`. CPU-время суммируется по ядрам,
поэтому за одну реальную секунду процесс может потратить несколько секунд CPU-времени.
Для прошедшего времени используется монотонный `Stopwatch`, а не часы Windows.

Первый замер даёт только начальное значение; проценты появятся после второго.
Отсутствие данных обозначаем `null` и показываем как «—». Пустое значение не означает
нулевую нагрузку. Если счётчик недоступен или пауза между замерами больше 60 секунд,
оставляем пробел в истории. Новые замеры не перекрываются: флаг `sampling` защищает
от запуска второго чтения, пока первое не завершилось.

PID может быть использован Windows повторно. Поэтому ключ истории — `ProcessIdentity`,
пара из PID и времени запуска. Путь успешно прочитанного процесса кешируется по этому
ключу. Завершившийся или недоступный при последнем обходе процесс некоторое время
остаётся в таблице как `Not observed`; новые CPU и RAM для него не придумываются.

История состоит из интервалов: начало, конец и процент CPU. Среднее взвешено по
длительности: двухсекундный замер имеет вдвое больший вес, чем секундный. При удалении
старых данных интервал на границе минуты обрезается. Это приближение: внутри каждого
интервала считаем нагрузку постоянной. Пик — максимум среди оставшихся интервалов.

В таблице хранятся числа, а формат `N1` только меняет их вид. Поэтому 60% сортируется
выше 9,5%. Перед обновлением запоминаем выбранный процесс и направление сортировки.
`SortCompare` отдельно обрабатывает отсутствующие значения: они всегда после чисел,
даже при сортировке по возрастанию. `CellFormatting` показывает вместо пустой ячейки
`Waiting`, `No access`, `No samples` или `Not seen`, сохраняя исходное значение `null`.

Поставь breakpoint на вычислении `current` в `ProcessHistory.cs`. Сравни `cpu`,
`previous`, `elapsed` и `processorCount` и посчитай результат сам. Учти: остановка
отладчиком создаёт паузу, и после 60 секунд этот интервал будет пропущен.

Для автоматической проверки:

```powershell
dotnet run --project tests/PCInspector.Checks --configuration Release -- --process-live
```

Первое самостоятельное изменение: добавь поиск по имени процесса. Фильтруй только
вывод таблицы, сохраняя сбор и историю всех процессов. Так очистка поиска сразу
вернёт накопленные данные.
